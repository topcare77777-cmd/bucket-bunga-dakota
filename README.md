Berikut adalah struktur folder dan file lengkap tanpa satu baris kode pun.

1. Root Directory (Level Repositori)
Folder:

.github/: Menyimpan konfigurasi otomatisasi pipeline (CI/CD) untuk memastikan setiap perubahan diuji dan di-deploy secara konsisten selama bertahun-tahun.

docs/: Pusat dokumentasi teknis, arsitektur, dan Handbook Project.

backend/: Mengisolasi seluruh ekosistem server, API, dan koneksi database.

frontend/: Mengisolasi ekosistem antarmuka pengguna (User Interface).

File:

docker-compose.yml: Mengatur orkestrasi container lokal (Database, Redis, Backend, Frontend) agar environment development selalu identik di mesin mana pun.

.gitignore: Mencegah file rahasia atau file build terunggah ke repositori.

README.md: Panduan utama repositori untuk orientasi developer baru.

2. Backend Directory (/backend)
Folder src/config/
Fungsi: Mengelola semua pengaturan lingkungan (environment) dan koneksi pihak ketiga.

database.ts: Menginisiasi koneksi pool ke database utama (PostgreSQL).

env_config.ts: Memvalidasi dan mengekspor seluruh variabel lingkungan (variabel .env) secara terpusat.

redis_client.ts: Mengatur koneksi ke Redis untuk caching dan antrean (queue) tugas berat.

Folder src/models/
Fungsi: Mendefinisikan entitas data dan skema interaksi dengan database (menggunakan ORM seperti Prisma/TypeORM).

user_model.ts: Entitas pengguna, peran (role), dan otorisasi.

campaign_model.ts: Entitas proyek kampanye (menyimpan metadata kampanye promosi, target audiens, dan tenggat waktu).

promotional_asset_model.ts: Entitas untuk menyimpan referensi file, jenis produk (misal: pakaian, parfum), format resolusi, dan URL penyimpanan.

review_annotation_model.ts: Entitas logikal untuk menyimpan komentar peninjauan yang terikat pada timestamp video atau koordinat piksel gambar.

Folder src/controllers/
Fungsi: Menangani masuknya permintaan HTTP (Request), memanggil fungsi di Service, dan mengembalikan respon (Response). Tidak ada logika bisnis di sini.

auth_controller.ts: Menangani proses login, logout, dan pembaruan token.

campaign_controller.ts: Menangani permintaan pembuatan, pembaruan, dan pengambilan daftar proyek kampanye.

asset_controller.ts: Menangani proses penerimaan unggahan file aset kreatif dari pengguna.

review_controller.ts: Menangani permintaan penambahan atau pengambilan catatan revisi/anotasi pada suatu aset.

Folder src/services/
Fungsi: Jantung aplikasi. Menyimpan seluruh Logika Bisnis (Business Logic). Sangat krusial untuk skalabilitas jangka panjang.

auth_service.ts: Memvalidasi kredensial, melakukan hashing password, dan menerbitkan JWT.

campaign_service.ts: Logika untuk mengubah status kampanye, menghitung persentase penyelesaian proyek, dan manajemen tim.

media_processing_service.ts: Logika khusus untuk menangani file berat, memicu antrean untuk transcoding video vertikal (9:16) agar dapat dipratinjau di web tanpa lag, serta kompresi gambar resolusi tinggi.

notification_service.ts: Mengirimkan peringatan (email/in-app) saat desain baru diunggah atau butuh persetujuan.

Folder src/middlewares/
Fungsi: Penjaga gerbang yang mencegat permintaan sebelum masuk ke Controller.

require_auth.ts: Memastikan pengguna memiliki token JWT yang valid.

role_guard.ts: Membatasi akses endpoint khusus (misal: hanya Creative Director yang bisa menyetujui kampanye).

file_validator.ts: Memeriksa ekstensi, tipe MIME, dan ukuran file materi pemasaran sebelum diizinkan masuk ke server.

error_handler.ts: Menangkap semua error yang bocor agar server tidak crash dan merespon dengan format JSON yang rapi.

Folder src/routes/
Fungsi: Memetakan URL Endpoint (misal: /api/campaigns) ke Controller yang tepat.

api_router.ts: Induk router yang menggabungkan semua sub-router di bawahnya.

auth_routes.ts: Rute khusus autentikasi.

campaign_routes.ts: Rute CRUD kampanye.

asset_routes.ts: Rute manajemen unggahan dan unduhan aset digital.

3. Frontend Directory (/frontend)
Folder src/app/
Fungsi: Menangani sistem perutean (Routing) halaman menggunakan arsitektur modern Next.js.

layout.tsx: Kerangka pembungkus utama HTML dan integrasi navigasi global (Sidebar/Navbar).

page.tsx: Halaman depan (Landing page) atau redirect ke Dashboard.

(auth)/login/page.tsx: Halaman antarmuka untuk masuk ke dalam sistem.

(dashboard)/overview/page.tsx: Halaman utama dasbor yang merangkum metrik proyek dan notifikasi.

(dashboard)/campaigns/page.tsx: Halaman daftar seluruh kampanye aktif.

(dashboard)/campaigns/[id]/page.tsx: Halaman detail spesifik dari satu kampanye beserta linimasanya.

(workspace)/review/[assetId]/page.tsx: Halaman khusus ruang kerja persetujuan dengan kanvas video/gambar layar penuh untuk melakukan anotasi.

Folder src/components/
Fungsi: Menyimpan blok antarmuka visual agar dapat digunakan berulang kali (Reusability).

ui/button.tsx: Komponen tombol standar dengan variasi status (loading, disabled).

ui/modal.tsx: Komponen pop-up melayang untuk konfirmasi aksi.

layout/sidebar.tsx: Komponen navigasi menu di sebelah kiri layar.

campaign/campaign_card.tsx: Komponen kartu yang menampilkan cuplikan info satu proyek kampanye.

media/vertical_video_player.tsx: Komponen pemutar video khusus yang dioptimalkan untuk rasio 9:16 dengan kontrol timeline khusus untuk review.

review/annotation_canvas.tsx: Komponen lapisan transparan di atas media untuk menggambar titik atau memberikan kotak komentar pada area spesifik (seperti menyoroti botol produk atau area kain).

Folder src/hooks/
Fungsi: Menyimpan logika reaktif client-side yang dapat digunakan berulang (Custom React Hooks).

use_auth.ts: Mengelola status sesi login pengguna di sisi client.

use_media_reviewer.ts: Mengelola state terkait peninjauan media, seperti posisi durasi video (timestamp) saat pengguna menekan tombol jeda untuk memberi revisi.

Folder src/store/
Fungsi: Manajemen State Global untuk data yang melintas antar halaman secara dinamis.

workspace_store.ts: Menyimpan data sementara tentang filter aktif, status panel sebelah kanan (terbuka/tertutup), dan tab navigasi pengguna.

Folder src/lib/
Fungsi: Konfigurasi klien layanan pihak ketiga dan modul utilitas eksternal.

api_client.ts: Konfigurasi fetcher (seperti Axios/Fetch API) dengan injeksi token otomatis ke header.

date_formatter.ts: Fungsi murni untuk mengubah format waktu mesin ke format waktu baca manusia.

Folder src/types/
Fungsi: Definisi statis tipe data (TypeScript Interfaces) agar arsitektur tetap ketat dan mencegah bug tipe data selama 5 tahun ke depan.

api_response.d.ts: Standar bentuk balasan dari server.

campaign_types.d.ts: Struktur data spesifik untuk objek kampanye.

Berikut adalah Desain Basis Data (Database Design) untuk sistem Manajemen Kampanye Promosi Digital. Sesuai dengan instruksi, tidak ada satu baris kode pun di tahap ini. Fokus kita adalah pada struktur logis, skalabilitas 5 tahun, integritas relasional, dan strategi pemeliharaan.

1. Entity-Relationship Diagram (ERD) & Konsep Inti
Desain ini menggunakan arsitektur relasional standar. Terdapat empat entitas utama yang saling berhubungan:

Pengguna (User) dapat memiliki banyak Kampanye (Campaign) (Relasi One-to-Many).

Satu Kampanye (misalnya: "Peluncuran Parfum Mewah Q3") menampung banyak Aset (Asset) visual dan video (Relasi One-to-Many).

Satu Aset (misalnya: Video vertikal 9:16 untuk media sosial) dapat memiliki banyak Ulasan/Anotasi (Review) dari berbagai pengguna/pengarah kreatif (Relasi One-to-Many).

2. Struktur Tabel, Kunci, dan Indeks
A. Tabel users
Menyimpan data autentikasi dan peran anggota tim.

Kolom Utama: id (UUID, Primary Key), full_name (String), email (String, Unik), password_hash (String), role (Enum: Admin, Creative_Director, Designer, Reviewer), created_at (Timestamp).

Index: B-Tree Index pada email untuk pencarian login yang instan.

B. Tabel campaigns
Menyimpan metadata proyek promosi digital.

Kolom Utama: id (UUID, Primary Key), title (String), description (Text), status (Enum: Draft, Active, Review, Completed, Archived), start_date (Date), end_date (Date), created_by (UUID, Foreign Key merujuk ke users.id), created_at (Timestamp).

Index: Index pada status dan created_by untuk mempercepat pemuatan dasbor saat memfilter kampanye yang sedang berjalan.

C. Tabel assets
Menyimpan informasi materi pemasaran, baik berupa gambar resolusi tinggi untuk cetak maupun video untuk apparel atau produk lainnya. (Sistem tidak menyimpan file mentah di database, melainkan menyimpan URL dari cloud storage).

Kolom Utama: id (UUID, Primary Key), campaign_id (UUID, Foreign Key merujuk ke campaigns.id), uploaded_by (UUID, Foreign Key merujuk ke users.id), file_name (String), media_type (Enum: Video, Image, Document), file_url (String), resolution (String), status (Enum: Pending, Approved, Rejected), created_at (Timestamp).

Index: Index gabungan (Composite Index) pada campaign_id dan status agar memuat galeri materi yang butuh persetujuan menjadi sangat cepat.

D. Tabel asset_reviews
Menyimpan catatan spesifik, revisi, atau penolakan pada materi tertentu.

Kolom Utama: id (UUID, Primary Key), asset_id (UUID, Foreign Key merujuk ke assets.id), reviewer_id (UUID, Foreign Key merujuk ke users.id), annotation_text (Text), video_timestamp_seconds (Integer, Opsional, penanda waktu jeda video), pos_x (Float, Opsional, koordinat klik area gambar), pos_y (Float, Opsional), status (Enum: Open, Resolved).

Index: Index pada asset_id agar saat video diputar, seluruh catatan pada file tersebut dapat dimuat secara real-time.

3. Strategi Optimasi Query (Skalabilitas 5 Tahun)
Untuk memastikan tidak ada penurunan performa saat tabel mencapai jutaan baris data dalam 5 tahun:

Cursor-Based Pagination: Pengambilan data daftar kampanye atau aset tidak akan menggunakan metode OFFSET konvensional (yang melambat pada data besar), melainkan menggunakan referensi id dan timestamp terakhir (Cursor).

Partial Indexing: Indeks hanya akan diterapkan pada kampanye dengan status aktif. Kampanye yang diarsipkan tidak akan membebani memori indeks (RAM) database.

Data Partitioning: Mempersiapkan partisi tabel (Table Partitioning) pada tabel asset_reviews berdasarkan tahun, sehingga kueri sistem hanya memindai data pada tahun yang relevan.

4. Strategi Pencadangan (Backup Strategy)
Point-in-Time Recovery (PITR): Pencatatan Write-Ahead Logs (WAL) akan diaktifkan. Ini memungkinkan kita mengembalikan (restore) kondisi database ke detik yang spesifik jika terjadi kesalahan fatal (misal: terhapusnya data penting).

Daily Full Backup: Salinan penuh database secara otomatis dibuat setiap tengah malam di jam dengan lalu lintas terendah, lalu dikirim ke penyimpanan terisolasi yang berbeda lokasi (off-site cloud storage).

Kebijakan Retensi:

Backup harian disimpan selama 30 hari.

Backup mingguan disimpan selama 3 bulan.

Backup bulanan (Archive) disimpan selama 5 tahun.

5. Strategi Migrasi (Migration Strategy)
Perubahan skema (seperti penambahan tabel atau kolom baru di masa depan) diatur dengan ketat:

Version Control: Setiap perubahan database harus dicatat dalam file migrasi berurut (misal: 001_init.sql, 002_add_duration_to_assets.sql).

Zero Downtime Migration: Setiap penambahan kolom tidak boleh mengunci tabel. Operasi yang memblokir penulisan (seperti Exclusive Locks) akan dihindari dengan menjalankan pembuatan indeks di latar belakang (CREATE INDEX CONCURRENTLY).

Rollback Plan (Script Down): Setiap script migrasi maju (Up) selalu didampingi dengan script pembalikan (Down) untuk membatalkan perubahan instan jika ditemukan anomali di tahap produksi.

Berikut adalah rancangan UI Design System untuk proyek ini. Sistem desain ini disusun dengan pendekatan minimalis, modern, dan premium—memberikan kanvas antarmuka yang bersih agar materi visual, seperti aset komersial parfum mewah dan desain kampanye pakaian, tetap menjadi pusat perhatian (focal point) di layar tanpa terdistraksi oleh elemen UI yang mencolok.

1. Color Palette (Palet Warna)
Palet warna dirancang untuk mendukung mode terang (Light Mode) dan persiapan mode gelap (Dark Mode).

Warna Utama (Primary): Onyx Black (#121212) dan Pure White (#FFFFFF) untuk mendominasi latar belakang dan teks, menciptakan kontras yang tajam dan profesional.

Warna Aksen (Accent): Champagne Gold (#D4AF37) atau Muted Indigo (#4F46E5) digunakan secara sangat selektif untuk tombol tindakan utama (Call to Action) dan indikator status aktif.

Warna Semantik (Semantic):

Emerald Green (#10B981) untuk status "Disetujui" (Approved).

Amber (#F59E0B) untuk status "Menunggu/Revisi" (Pending/Revision).

Rose Red (#EF4444) untuk status "Ditolak" (Rejected) atau pesan error.

Warna Netral (Grayscale): Skala abu-abu dari Slate-50 hingga Slate-900 untuk garis tepi (border), bayangan (shadow), dan teks sekunder.

2. Typography (Tipografi)
Tipografi menggunakan kombinasi font yang mendukung keterbacaan tinggi di berbagai ukuran layar.

Heading & Titles: Display Sans-Serif (seperti Clash Display atau Outfit) dengan ketebalan Medium hingga Bold. Memberikan kesan elegan pada judul kampanye.

Body Text & UI Elements: Inter atau Geist Sans. Font dengan proporsi metrik yang sempurna untuk elemen UI padat karya, tombol, dan teks paragraf.

Hierarchy:

H1: 32px (Line height 1.2)

H2: 24px (Line height 1.3)

Body: 16px (Line height 1.5)

Caption: 12px (Line height 1.4)

3. Spacing (Sistem Jarak)
Menggunakan 8-Point Grid System untuk memastikan proporsi matematis yang konsisten di seluruh antarmuka.

Micro: 4px, 8px (untuk jarak antar ikon dan teks dalam tombol).

Base: 16px, 24px (untuk padding dalam kartu atau jarak antar elemen formulir).

Macro: 32px, 48px, 64px (untuk pemisah antar bagian halaman atau margin utama).

4. Button (Tombol)
Sistem tombol dirancang dengan empat state utama: Default, Hover, Active/Pressed, Disabled.

Primary Button: Latar belakang solid (warna aksen atau hitam pekat), teks putih. Sudut membulat halus (border-radius: 6px).

Secondary/Outline Button: Tanpa latar belakang, memiliki garis tepi (border) 1px, warna teks menyesuaikan border. Digunakan untuk aksi sekunder seperti "Batal".

Ghost Button: Tanpa latar belakang dan tanpa garis tepi. Digunakan untuk aksi tersier.

5. Card (Kartu)
Digunakan sebagai wadah utama untuk menampilkan thumbnail kampanye dan aset media.

Visual: Latar belakang putih solid, border-radius 8px, garis tepi (border) super tipis 1px Slate-200.

Elevasi (Shadow): Bayangan sangat lembut (soft drop shadow) yang hanya muncul atau menebal ketika kursor diarahkan ke atas kartu (Hover state), memberikan ilusi interaktif yang elegan.

6. Navbar (Bilah Navigasi)
Tipe: Sticky Top (menempel di atas layar saat digulir).

Komponen: Logo aplikasi di kiri, Breadcrumb (jalur navigasi) di tengah untuk orientasi ruang kerja, dan profil pengguna serta lonceng notifikasi di kanan. Latar belakang putih dengan efek blur/frosted glass halus saat halaman digulir.

7. Footer
Desain Minimalis: Ditempatkan di bagian paling bawah halaman dengan tinggi minimal. Hanya memuat teks hak cipta, versi aplikasi (misal: v1.0.0), dan tautan cepat ke "Bantuan" atau "Dokumentasi".

8. Animation (Animasi & Transisi)
Animasi dibuat fungsional dan tidak berlebihan, berfokus pada pengalaman yang mulus.

Micro-interactions: Transisi perubahan warna tombol atau hover kartu menggunakan durasi 200ms dengan timing function ease-in-out.

Page Transitions: Efek fade-in sangat cepat (300ms) saat berpindah antar halaman kampanye untuk menghindari kesan aplikasi lambat (lagging).

9. Responsive Rule (Aturan Responsif)
Pendekatan Mobile-First yang beradaptasi secara dinamis membesar ke ukuran desktop.

Mobile (sm - <640px): Navbar menyusut menjadi menu Hamburger. Grid kartu menjadi 1 kolom.

Tablet (md - 768px): Menu Sidebar dapat diciutkan (collapsible). Grid kartu 2 kolom.

Desktop (lg - 1024px & xl - 1280px+): Ruang kerja kanvas maksimal. Peninjauan video vertikal 9:16 diposisikan di tengah dengan panel komentar revisi (Anotasi) berdampingan di sebelah kanan layar (Split-view).

10. Dark Mode Preparation (Persiapan Mode Gelap)
Struktur disiapkan agar dapat beralih tema dengan mudah melalui CSS Variables.

Aturan Warna: Warna putih murni tidak akan dibalik menjadi hitam murni (#000000) untuk mencegah kelelahan mata. Sebaliknya, menggunakan Dark Slate (#0F172A) untuk latar belakang utama, dan Slate lebih terang (#1E293B) untuk kartu (elevasi warna).

Desaturasi Aksen: Warna hijau, merah, dan kuning pada status diturunkan saturasinya (desaturated) agar tidak menyilaukan di atas latar belakang gelap.

11. Accessibility (Aksesibilitas - Standar WCAG 2.1 AA)
Rasio Kontras: Semua teks utama memiliki rasio kontras minimal 4.5:1 terhadap latar belakangnya.

Focus Ring: Garis tepi fokus (outline) berwarna biru atau emas yang jelas terlihat saat pengguna melakukan navigasi menggunakan keyboard (tombol Tab).

Screen Reader: Seluruh ikon interaktif dan elemen tanpa teks (seperti tombol "Play" pada video pratinjau) akan dilengkapi dengan ARIA labels untuk perangkat pembaca layar.

Struktur Modul & Fungsi Admin Panel
1. Dashboard (Dasbor Utama)

Ringkasan Metrik (Overview): Kartu statistik yang menampilkan Total Produk Aktif, Total Ukuran Media (Storage Used), dan Jumlah Administrator.

Grafik Aktivitas: Visuliasasi data penambahan produk atau unggahan media dalam 30 hari terakhir.

Aktivitas Terbaru (Recent Activity): Feed singkat yang menunjukkan siapa melakukan apa (misal: "Admin A baru saja memperbarui harga produk").

2. Produk (Manajemen Inventaris/Katalog)

Daftar Produk: Tabel dengan fitur pencarian, filter, dan pagination. Menampilkan SKU, Nama Produk, Kategori, Harga, dan Status (Draft/Published).

Tambah/Edit Produk: Formulir input data produk, pengaturan SEO (Meta Title, Meta Description), dan tautan langsung ke aset spesifik di Gallery.

Varian Produk: Pengaturan atribut dinamis (seperti ukuran untuk pakaian atau volume mililiter untuk parfum).

3. Kategori (Taksonomi Produk)

Pohon Kategori (Category Tree): Tampilan hierarki kategori (Induk dan Anak kategori), mendukung drag-and-drop untuk mengatur ulang susunan.

Manajemen Kategori: Form untuk membuat kategori baru, menetapkan gambar thumbnail kategori, dan mengatur URL Slug.

4. Media (Pustaka Aset Digital Terpusat)

Grid/List View: Menampilkan seluruh file yang ada di server.

Pencarian & Filter Media: Filter berdasarkan format file (Video, Image, Document), orientasi (misal: vertikal 9:16, landscape), dan rentang tanggal.

Detail Media: Panel sebelah kanan yang menampilkan metadata file (ukuran file, resolusi, tautan URL publik, dan kapan diunggah).

5. Gallery (Album & Kurasi Visual)

Manajemen Album: Pengelompokan media menjadi sebuah Gallery tematik (misal: "Koleksi Musim Panas 2026").

Penyortiran Media: Antarmuka visual untuk mengatur urutan gambar/video di dalam galeri (penting untuk tampilan carousel di halaman depan).

6. Upload (Pusat Unggahan Berkinerja Tinggi)

Area Dropzone: Area luas untuk menyeret dan melepas (drag-and-drop) banyak file sekaligus.

Manajemen Antrean (Upload Queue): Menampilkan bilah proses (progress bar) untuk setiap file, mendeteksi file duplikat, dan menangani unggahan file video berukuran besar menggunakan sistem chunking (pemotongan data).

7. Pengaturan (Konfigurasi Sistem Global)

Identitas Situs: Pengaturan Nama Situs, Logo Utama, Favicon, dan Email Kontak.

Preferensi Tampilan: Opsi untuk mengatur zona waktu sistem, format tanggal, dan batas unggahan per file.

Integrasi Pihak Ketiga: Kolom untuk memasukkan kunci API (API Keys) untuk layanan eksternal (misal: layanan SMTP untuk email, atau kunci Cloud Storage).

8. Backup (Manajemen Keamanan Data)

Pencadangan Manual: Tombol untuk memicu pembuatan arsip database (.sql) dan aset media (.zip) secara instan.

Riwayat Pencadangan: Daftar file backup yang tersedia di server beserta ukurannya, lengkap dengan tombol untuk Unduh atau Pulihkan (Restore).

9. Log (Jejak Audit & Pemantauan)

Log Akses: Catatan detail setiap kali ada upaya masuk (login) ke Admin Panel (Alamat IP, Waktu, Perangkat, dan Status Berhasil/Gagal).

Log Kesalahan (Error Logs): Daftar error teknis yang terjadi di latar belakang untuk memudahkan debugging tanpa harus membuka server secara langsung.

10. Administrator (Manajemen Tim Internal)

Daftar Pengguna Admin: Tabel yang berisi daftar akun dengan akses ke belakang layar.

Role-Based Access Control (RBAC): Sistem perizinan ketat. (Misal: Peran 'Editor' hanya bisa mengakses menu Produk dan Media, sedangkan akses ke Pengaturan, Backup, dan Log dibatasi khusus untuk peran 'Super Admin').

Log Aktivitas Individu: Melacak perubahan spesifik yang dilakukan oleh masing-masing administrator.

1. Kesenjangan Struktur Database (Kritikal)
Desain awal kita hanya memiliki tabel users, campaigns, assets, dan asset_reviews. Kita wajib menambahkan entitas baru untuk mengakomodasi Admin Panel:

Tabel products & product_variants: Untuk menyimpan data master SKU, harga, dan variasi dinamis (misalnya ukuran untuk lini pakaian atau opsi volume mililiter untuk koleksi parfum).

Tabel categories: Untuk taksonomi hierarkis produk.

2. Layanan Bisnis (src/services/product_service.ts)
Mengelola manipulasi data langsung ke database PostgreSQL menggunakan abstraksi kueri yang aman dari SQL Injection.

TypeScript
import pool from '../config/database';
import { generateSecureToken } from '../utils/helper';

export interface ProductInput {
  name: string;
  category_id: string;
  price: number;
  description?: string;
  status: 'READY' | 'SOLD';
  sku: string;
}

export class ProductService {
  static async createProduct(input: ProductInput, userId: string) {
    const queryText = `
      INSERT INTO products (id, name, category_id, price, description, status, sku, created_by, created_at)
      VALUES (gen_random_uuid(), $1, $2, $3, $4, $5, $6, $7, NOW())
      RETURNING *;
    `;
    const values = [input.name, input.category_id, input.price, input.description || null, input.status, input.sku, userId];
    const result = await pool.query(queryText, values);
    return result.rows[0];
  }

  static async getProducts(page: number, limit: number, search?: string) {
    const offset = (page - 1) * limit;
    let queryText = `SELECT p.*, c.name as category_name FROM products p LEFT JOIN categories c ON p.category_id = c.id`;
    const values: any[] = [];

    if (search) {
      queryText += ` WHERE p.name ILIKE $1 OR p.sku ILIKE $1`;
      values.push(`%${search}%`);
    }

    queryText += ` ORDER BY p.created_at DESC LIMIT $${values.length + 1} OFFSET $${values.length + 2}`;
    values.push(limit, offset);

    const dataResult = await pool.query(queryText, values);
    
    const countText = search ? `SELECT COUNT(*) FROM products WHERE name ILIKE $1 OR sku ILIKE $1` : `SELECT COUNT(*) FROM products`;
    const countResult = await pool.query(countText, search ? [`%${search}%`] : []);
    
    return {
      products: dataResult.rows,
      total: parseInt(countResult.rows[0].count, 10)
    };
  }

  static async getProductById(id: string) {
    const queryText = `SELECT p.*, c.name as category_name FROM products p LEFT JOIN categories c ON p.category_id = c.id WHERE p.id = $1`;
    const result = await pool.query(queryText, [id]);
    return result.rows[0] || null;
  }

  static async updateProduct(id: string, input: Partial<ProductInput>) {
    const fields: string[] = [];
    const values: any[] = [];
    let idx = 1;

    Object.entries(input).forEach(([key, value]) => {
      if (value !== undefined) {
        fields.push(`${key} = $${idx}`);
        values.push(value);
        idx++;
      }
    });

    if (fields.length === 0) return null;

    values.push(id);
    const queryText = `UPDATE products SET ${fields.join(', ')}, updated_at = NOW() WHERE id = $${idx} RETURNING *`;
    const result = await pool.query(queryText, values);
    return result.rows[0] || null;
  }

  static async deleteProduct(id: string) {
    const queryText = `DELETE FROM products WHERE id = $1 RETURNING id`;
    const result = await pool.query(queryText, [id]);
    return result.rowCount > 0;
  }
}

import { Request, Response } from 'express';
import { ProductService } from '../services/product_service';
import { ApiResponse } from '../core/response';
import { HTTP_STATUS } from '../config/constants';

export class ProductController {
  static async create(req: Request, res: Response) {
    try {
      const userId = req.user?.id || '00000000-0000-0000-0000-000000000000'; 
      const newProduct = await ProductService.createProduct(req.body, userId);
      return ApiResponse.success(res, newProduct, 'Produk berhasil ditambahkan', HTTP_STATUS.CREATED);
    } catch (error: any) {
      return ApiResponse.error(res, error.message, HTTP_STATUS.INTERNAL_SERVER_ERROR);
    }
  }

  static async list(req: Request, res: Response) {
    try {
      const page = parseInt(req.query.page as string || '1', 10);
      const limit = parseInt(req.query.limit as string || '10', 10);
      const search = req.query.search as string || undefined;

      const { products, total } = await ProductService.getProducts(page, limit, search);
      return ApiResponse.paginate(res, products, total, page, limit, 'Daftar produk berhasil dimuat');
    } catch (error: any) {
      return ApiResponse.error(res, error.message, HTTP_STATUS.INTERNAL_SERVER_ERROR);
    }
  }

  static async detail(req: Request, res: Response) {
    try {
      const product = await ProductService.getProductById(req.params.id);
      if (!product) {
        return ApiResponse.error(res, 'Produk tidak ditemukan', HTTP_STATUS.NOT_FOUND);
      }
      return ApiResponse.success(res, product, 'Detail produk berhasil dimuat');
    } catch (error: any) {
      return ApiResponse.error(res, error.message, HTTP_STATUS.INTERNAL_SERVER_ERROR);
    }
  }

  static async update(req: Request, res: Response) {
    try {
      const updatedProduct = await ProductService.updateProduct(req.params.id, req.body);
      if (!updatedProduct) {
        return ApiResponse.error(res, 'Produk tidak ditemukan untuk diperbarui', HTTP_STATUS.NOT_FOUND);
      }
      return ApiResponse.success(res, updatedProduct, 'Produk berhasil diperbarui');
    } catch (error: any) {
      return ApiResponse.error(res, error.message, HTTP_STATUS.INTERNAL_SERVER_ERROR);
    }
  }

  static async delete(req: Request, res: Response) {
    try {
      const isDeleted = await ProductService.deleteProduct(req.params.id);
      if (!isDeleted) {
        return ApiResponse.error(res, 'Produk tidak ditemukan untuk dihapus', HTTP_STATUS.NOT_FOUND);
      }
      return ApiResponse.success(res, { id: req.params.id }, 'Produk berhasil dihapus');
    } catch (error: any) {
      return ApiResponse.error(res, error.message, HTTP_STATUS.INTERNAL_SERVER_ERROR);
    }
  }
}

import sharp from 'sharp';
import path from 'path';
import fs from 'fs';
import { generateSecureToken } from '../utils/helper';

const UPLOAD_DIR = path.join(__dirname, '../../uploads');

export class ImageService {
  static async processImage(buffer: Buffer, filename: string) {
    if (!fs.existsSync(UPLOAD_DIR)) fs.mkdirSync(UPLOAD_DIR, { recursive: true });

    const baseName = generateSecureToken(8);
    const fileName = `${baseName}.webp`;
    const thumbName = `thumb_${baseName}.webp`;

    // 1. Process Main Image (Resize, Compress, WebP)
    await sharp(buffer)
      .resize(1200, 1200, { fit: 'inside', withoutEnlargement: true })
      .webp({ quality: 80 })
      .toFile(path.join(UPLOAD_DIR, fileName));

    // 2. Process Thumbnail (Resize to 200x200)
    await sharp(buffer)
      .resize(200, 200, { fit: 'cover' })
      .webp({ quality: 70 })
      .toFile(path.join(UPLOAD_DIR, thumbName));

    return { fileName, thumbName };
  }
}

1. Konfigurasi Skrip Utility (src/utils/db_manager.ts)
Skrip ini akan mengeksekusi perintah sistem untuk berinteraksi dengan database.

TypeScript
import { exec } from 'child_process';
import util from 'util';
import logger from '../utils/logger';

const execPromise = util.promisify(exec);

// Konfigurasi Database
const DB_CONN = `postgresql://${process.env.DB_USER}:${process.env.DB_PASSWORD}@${process.env.DB_HOST}:${process.env.DB_PORT}/${process.env.DB_NAME}`;

export class DatabaseManager {
  
  // 1. Backup: Dump seluruh database ke file .sql
  static async backup(outputPath: string) {
    try {
      await execPromise(`pg_dump ${DB_CONN} > ${outputPath}`);
      logger.info(`Backup database berhasil disimpan di: ${outputPath}`);
    } catch (error) {
      logger.error('Backup database gagal', error);
      throw error;
    }
  }

  // 2. Restore: Mengembalikan database dari file .sql
  static async restore(inputPath: string) {
    try {
      await execPromise(`psql ${DB_CONN} < ${inputPath}`);
      logger.info(`Restore database berhasil dari: ${inputPath}`);
    } catch (error) {
      logger.error('Restore database gagal', error);
      throw error;
    }
  }

  // 3. Export: Ekspor tabel tertentu ke CSV
  static async exportToCsv(tableName: string, outputPath: string) {
    try {
      const query = `COPY ${tableName} TO STDOUT WITH CSV HEADER`;
      await execPromise(`psql ${DB_CONN} -c "${query}" > ${outputPath}`);
      logger.info(`Data tabel ${tableName} berhasil diekspor ke: ${outputPath}`);
    } catch (error) {
      logger.error('Export ke CSV gagal', error);
      throw error;
    }
  }

  // 4. Import: Impor data dari CSV ke tabel
  static async importFromCsv(tableName: string, inputPath: string) {
    try {
      const query = `COPY ${tableName} FROM STDIN WITH CSV HEADER`;
      await execPromise(`psql ${DB_CONN} -c "${query}" < ${inputPath}`);
      logger.info(`Data berhasil diimpor ke tabel ${tableName} dari: ${inputPath}`);
    } catch (error) {
      logger.error('Import dari CSV gagal', error);
      throw error;
    }
  }
}

Untuk melanjutkan langkah terakhir dalam siklus pengembangan aplikasi PromoMgr, kita akan masuk ke tahap Deployment Setup (CI/CD). Tahap ini akan memastikan kode Anda diuji, dibangun, dan disebarkan secara otomatis ke server produksi dengan aman.

Berikut adalah konfigurasi pipeline untuk GitHub Actions yang memastikan Deployment berjalan tanpa henti (Zero-Downtime Deployment).

1. Konfigurasi CI/CD (.github/workflows/deploy.yml)
Buat file ini di direktori root repositori Anda. Pipeline ini akan melakukan pengujian unit, build aplikasi, dan penyebaran otomatis ke server VPS via SSH.

YAML
name: Deploy PromoMgr Production

on:
  push:
    branches: [ main ]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '20'

      - name: Install Dependencies
        run: npm install

      - name: Run Unit Tests
        run: npm test # Menjalankan Jest untuk memastikan kode tidak rusak

      - name: Build Application
        run: npm run build

      - name: Deploy to VPS
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          script: |
            cd /var/www/promomgr
            git pull origin main
            npm install
            npm run build
            pm2 restart promomgr-app # Restart aplikasi dengan PM2 (Process Manager)
2. Strategi Deployment & Keamanan
Zero-Downtime dengan PM2: Kita menggunakan PM2 sebagai Process Manager di server. Perintah pm2 restart memastikan layanan tetap hidup meskipun proses re-deployment sedang berjalan.

Environment Secrets: Jangan pernah menuliskan password database atau API key di dalam file deploy.yml. Gunakan fitur GitHub Secrets untuk menyimpan SSH_PRIVATE_KEY, SERVER_HOST, dan DB_PASSWORD dengan aman.

Database Migration: Sebelum melakukan deploy, tambahkan langkah npx prisma migrate deploy (jika Anda menggunakan ORM) untuk memastikan skema database di server selalu sinkron dengan versi kode terbaru.

3. Checklist Terakhir Sebelum "Go-Live"
SSL/TLS: Pastikan sertifikat SSL (Let's Encrypt) terpasang di Nginx/Apache untuk mengaktifkan HTTPS.

Backup: Pastikan skrip backup yang kita buat di Tahap 22 sudah dijadwalkan secara otomatis menggunakan cron di Linux (misalnya dijalankan setiap jam 00:00).

Error Logging: Pastikan file logger.ts telah diarahkan ke file log yang benar di server agar Anda dapat memantau jika terjadi crash saat aplikasi berjalan.

# Digital Promo Campaign Manager

Digital Promo Campaign Manager adalah platform enterprise untuk manajemen kampanye pemasaran digital, kurasi galeri produk, dan sistem anotasi ulasan media (video dan gambar resolusi tinggi). Sistem ini dirancang khusus untuk memfasilitasi alur kerja kreatif antara Creative Director, Designer, dan Management.

## Arsitektur & Teknologi

*   **Frontend:** Next.js (App Router), React, Tailwind CSS, TypeScript.
*   **Backend:** Node.js, Express, TypeScript.
*   **Database:** PostgreSQL (Relasional Utama), Redis (Caching & Queue).
*   **Infrastruktur:** Docker, Docker Compose, Nginx.

## Persyaratan Sistem (System Requirements)

*   Node.js v20.x atau lebih baru
*   Docker & Docker Compose (v2.x)
*   PostgreSQL v15.x atau lebih baru
*   Redis v7.x

## Instalasi & Menjalankan Aplikasi Lokal

1. Kloning repositori ini.
2. Salin konfigurasi environment:
   `cp backend/.env.example backend/.env`
   `cp frontend/.env.example frontend/.env`
3. Jalankan infrastruktur container (Database & Redis):
   `docker-compose up -d`
4. Instalasi dependensi backend dan jalankan migrasi:
   `cd backend && npm install`
   `npm run migrate:up`
   `npm run dev`
5. Instalasi dependensi frontend:
   `cd frontend && npm install`
   `npm run dev`

Sistem akan berjalan di `http://localhost:3000` (Frontend) dan `http://localhost:8000` (Backend API).
